# PRD: Classic 专业化 UI 重构 (v35)

## 1. 背景
- 当前 classic 视觉已升级到 v34，但 HUD 信息组织仍偏平铺，专业演示时信息优先级不够清晰。
- 需要在不改玩法规则和体感控制链路的前提下，提升信息架构与界面表达。

## 2. 目标
- 将 classic 主界面重构为清晰的三层结构：主状态区、控制区、诊断区。
- 引入可折叠诊断区，默认弱化技术细节，保留调试可见性。
- 增强主题一致性与状态表达（RUNNING/PAUSED/GAME_OVER）。
- 在 `render_game_to_text` 增加 `uiVariant`，支持回归观察。

## 3. 范围
- 前端界面层：`web/index.html`、`web/styles.css`。
- 前端控制层：`web/game/index.js`（诊断折叠行为和 HUD 输出）。
- 游戏状态文本：`web/game/modes/classic.js`（新增 UI 观测字段）。
- 自动化：复用现有回归 + 人工试玩截图证据。

## 4. 方案
- 调整 HTML 结构为模块化区块，并新增诊断折叠按钮。
- CSS 建立统一组件样式（panel/chip/button），提升层次感和可读性。
- JS 接入 `diag` 展开/收起状态，并将状态映射到 `body` 数据属性。
- `render_game_to_text().visual` 新增 `uiVariant` 字段，值为 `classic-pro-v35`。

## 5. 验收标准
1. 界面分区明确，主状态区在首屏优先可读。
2. 诊断区可折叠，折叠不影响玩法和控制。
3. 现有回归脚本全部通过，玩法规则无变化。
4. 提供至少 1 张 v35 运行态证据截图与对应说明文档。

## 6. 风险与应对
- 风险: 结构重构影响现有 DOM 选择器导致测试失败。
- 应对: 保持已有关键 id 不变（`btnStart`、`diag*`、`avatarSkin`、`visualPreset` 等），仅调整容器层结构。
