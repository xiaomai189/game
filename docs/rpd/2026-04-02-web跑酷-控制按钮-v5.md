# PRD：Web 跑酷控制按钮 v5（启动/暂停/继续/重开）

## 背景
- 当前网页跑酷主要依赖后端状态推进，缺少显式控制按钮，演示时不够直观。
- 用户希望在网页界面直接控制游戏流程（启动、暂停、继续、重开）。

## 目标
- 在网页 HUD 增加控制按钮：`启动`、`暂停`、`继续`、`重开`。
- 跑酷状态机支持 `READY`、`RUNNING`、`PAUSED`、`GAME_OVER`，并与按钮联动。
- 保留现有手势换道/护盾逻辑，不改姿态识别链路。

## 范围
- In Scope：
  - 更新 `web/index.html`、`web/styles.css`、`web/game.js`。
  - 更新 README 中 Web 跑酷操作说明。
  - 执行 `npm run build` 验证。
  - 产出界面证据到 `docs/evidence/`。
- Out of Scope：
  - 不修改 Python 后端游戏引擎规则。
  - 不新增后端控制指令协议。

## 方案
- 新增控制区按钮并绑定事件：
  - `启动`：从 `READY/GAME_OVER` 初始化并进入 `RUNNING`。
  - `暂停`：从 `RUNNING` 切换到 `PAUSED`。
  - `继续`：从 `PAUSED` 返回 `RUNNING`。
  - `重开`：任意状态重置并进入 `RUNNING`。
- 前端本地维护倒计时（45s），在 `step()` 内按 `dt` 递减。
- `onPose()` 仅消费动作输入（换道与下蹲护盾），不再依赖后端 `status` 触发开局。
- 根据状态刷新按钮可用性与状态文案，减少误操作。

## 验收标准
- [ ] 页面显示控制按钮，按钮可点击且状态切换正确。
- [ ] 启动后障碍生成；暂停时画面冻结；继续后恢复；重开后分数和障碍重置。
- [ ] 手势换道与护盾逻辑保持可用。
- [ ] `npm run build` 成功。
- [ ] 界面证据已写入 `docs/evidence/`。

## 风险与缓解
- 风险：前端状态与后端状态文案出现认知差异。
- 缓解：HUD 显示“本地游戏状态”，并保留连接状态独立显示。
