# PRD：Classic 模式时间归零续时优化（v28）

## 1. 背景
- 当前 `Classic` 模式在 `Time` 倒计时到 `0` 时会立即进入 `GAME_OVER`。
- 用户反馈该行为导致“还想继续玩但被强制结束”，影响连续体验。

## 2. 目标
- 在 `Classic` 模式中，倒计时到 `0` 不再触发 `GAME_OVER`。
- 游戏继续运行，玩家仅在撞到错误通道时结束。

## 3. 范围
- 修改 `web/game/modes/classic.js` 的时间状态机。
- 增加自动化回归验证，确保后续不会回退为“时间到即结束”。
- 更新相关说明文案与变更记录。

## 4. 方案
- 将倒计时语义从“整局时长”调整为“循环节拍时长”。
- 每当 `timeLeftSec <= 0` 时，自动补回一个周期（`RUNNER_DURATION`），并继续 `RUNNING`。
- 保留碰撞失败逻辑不变：仅碰撞触发 `GAME_OVER`。

## 5. 验收标准
1. 点击开始后，在无碰撞情况下，`Time` 到 `0` 时不进入 `GAME_OVER`。
2. 倒计时应自动回到新的周期并继续下降。
3. 碰撞红色障碍仍会立即结束对局。
4. `npm run build`、现有 web 手势回归、预检脚本通过。

## 6. 风险与应对
- 风险：若回补时间逻辑处理不当，可能出现时间跳变或负值残留。
- 应对：使用循环回补（处理大帧间隔），并在回归脚本中验证状态始终为 `RUNNING`。
