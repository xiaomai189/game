# PRD：体感识别稳定性优化 v14（关键点短时丢失容错）

## 背景
- 当前换道状态机已优化，但在摄像头抖动或遮挡下，关键点会出现 1~2 帧短时丢失，导致动作状态瞬时抖动。
- 这类抖动会通过 WebSocket 传到网页玩法，表现为偶发误切道或动作闪断。

## 目标
- 在不改动作语义规则前提下，提升关键点短时丢失时的动作连续性。
- 保持速度优先，不引入明显额外延迟。

## 范围
- In Scope：
  - 在 `core/action_engine.py` 增加关键点短时保留（grace frames）机制。
  - 在 `config.py` 和 `main.py` 增加对应可配置项并接入。
  - 补充 `tests/test_action_engine.py` 的容错行为测试。
  - 执行 `pytest -q` 与 `npm run build` 验证。
  - 补充变更记录和证据说明。
- Out of Scope：
  - 不调整 Web 前端换道状态机参数（30ms/70ms）。
  - 不修改 YOLO 模型、推理参数和骨架绘制逻辑。

## 方案
- 为关键点（手腕、肩、髋、膝）增加“短时丢失保留”策略：
  - 若关键点当前帧置信度不足，但历史上一次有效点存在，且连续丢失帧数不超过阈值（默认 2 帧），则临时复用上次有效点。
  - 超过阈值后清空，避免长期使用陈旧点。
- 该策略用于动作判定输入层，动作规则本身保持不变。
- 新增配置：
  - `keypoint_grace_frames`（默认 2）。

## 验收标准
- [ ] 单帧关键点丢失不会立即导致动作状态闪断。
- [ ] 连续超过阈值丢失后，动作状态按预期回退为无效。
- [ ] `pytest -q` 通过。
- [ ] `npm run build` 通过。

## 风险与缓解
- 风险：短时复用历史点可能在快速大动作时引入 1~2 帧旧值。
- 缓解：默认仅保留 2 帧，并将阈值配置化，便于现场调参。
