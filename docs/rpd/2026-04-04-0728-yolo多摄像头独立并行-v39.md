# PRD: YOLO 多摄像头独立并行（v39）

## 1. 背景
- v38 已完成单摄双人识别与角色绑定，输出结构具备多人扩展能力。
- 下一阶段需要支持多摄像头并行，同时保持旧链路兼容，不做跨镜头融合。

## 2. 目标
- 支持 2 路及以上摄像头独立并行采集与推理。
- 每路独立输出动作、双人、角色绑定状态，互不污染。
- root payload 保持旧字段，新增 `cameras[]` 聚合多路状态。

## 3. 范围
- `config.py`：多摄默认配置项。
- `core/camera.py`：source 泛化（index / URL）。
- `main.py`：多路采集循环、独立 runtime、active camera 选择、payload 聚合。
- `tests/test_main_demo_action.py`：新增 camera source 解析测试。

## 4. 方案
- 新增 `--camera-sources`（逗号分隔）与 `--active-camera-id` 参数。
- 每路独立维护：
  - `PoseEngine`
  - `ActionEngine`
  - `PipelineStats` / 自适应控制器
  - `last_keypoints/persons/roles/warning`
- root 继续发布 active camera 数据；新增：
  - `activeCameraId`
  - `cameras[]`（每路 actions/persons/roles/pipeline）
- 单路异常不影响其他路；无可用路时降级等待/跳过。

## 5. 验收标准
1. 支持 `--camera-sources "0,1"` 启动并稳定运行（有硬件时并行处理）。
2. payload 根字段兼容旧消费端；`cameras[]` 可观测每路状态。
3. demo/no-display 下多摄参数不导致异常退出。
4. `pytest -q`、`npm run build`、`npm run preflight` 全通过。

## 6. 风险与应对
- 风险：多路状态耦合导致角色绑定串路。
- 应对：每路独立 `ActionEngine` 与 runtime 存储，按 camera_id 隔离。
