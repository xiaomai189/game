# PRD：Web 跑酷动画资源化 v19

## 背景
- v18 已完成程序化动效增强，但角色与障碍仍主要依赖 Canvas 即时绘制，视觉风格一致性和后续美术迭代效率受限。
- 需要引入可替换的美术资源，同时保证资源加载失败时不影响可玩性。

## 目标
- 将核心视觉元素切换为资产优先渲染（角色、障碍、背景分层）。
- 保留程序化回退路径，确保资源异常时游戏仍可运行。
- 在状态输出中暴露渲染模式与资源加载状态，便于自动化验证。

## 范围
- In Scope
  - `web/game.js`：新增资源清单、预加载、资产渲染函数、资产/回退模式切换。
  - `web/game.js`：`render_game_to_text` 新增资源化状态字段。
  - `web/assets/images/web-runner/`：新增角色、障碍、背景 SVG 资源。
  - 补充 v19 证据与变更记录。
- Out of Scope
  - 不调整手势判定与换道时序规则（30ms/70ms/300ms）。
  - 不改动 Python 端 YOLO 推理链路。

## 方案
- 资源层
  - 引入 `assetCatalog` 统一声明资源路径。
  - 启动时执行 `preloadAssets()`，成功进入 `asset-first`，失败按配置进入回退模式。
- 渲染层
  - 背景采用三层平铺（far/mid/near）+ 视差滚动。
  - 玩家与门体改为贴图渲染，并保留程序化绘制作为 fallback。
- 可观测性
  - `render_game_to_text.visual` 增加 `renderMode/assetsLoaded/assetTheme/assetFallbackEnabled/assetFallbackReason`。
  - 支持 URL 参数：`assetTheme`、`assetScale`、`assetFallbackEnabled`。

## 验收标准
- [ ] 角色、障碍、背景可通过 SVG 资源渲染，运行中无报错。
- [ ] 资源加载成功时 `visual.renderMode=asset-first` 且 `assetsLoaded=true`。
- [ ] 回退路径存在且在资源异常时可继续游戏。
- [ ] `npm run build`、`npm run test:web-gesture`、`pytest -q` 全通过。
- [ ] 产出 v19 截图与状态 JSON 证据。

## 风险与缓解
- 风险：资源体积增大导致首帧加载延迟。
- 缓解：当前使用轻量 SVG；预加载失败自动回退，避免阻断游戏主流程。
