# PRD: 双摄像头打开回退与诊断增强（v40）
## 1. 背景
- v39 已支持 `--camera-sources "0,1"` 多路输入，但现场运行中出现 `CAP_DSHOW` 对部分索引无法打开，导致第二路被跳过。
- 当前报错只提示“无法打开 source”，对实际尝试的后端和失败过程不可见，排障效率低。

## 2. 目标
- 提升 Windows 相机打开兼容性：索引相机默认尝试多后端回退，而不是只试一次 DSHOW。
- 增强诊断信息：明确显示“尝试过哪些后端、最终使用哪个后端、失败原因是什么”。
- 不影响现有 URL/RTSP 源和单路流程。

## 3. 范围
- `core/camera.py`
  - 增加索引源的后端回退策略。
  - 增加打开结果元信息（最终后端名、失败尝试列表）。
  - 改进异常消息，包含可操作的排障线索。
- `tests/`
  - 增加 `core/camera.py` 的单元测试，覆盖回退成功和全部失败场景。
- 文档
  - 补充 change-log 和记要。

## 4. 方案
- 对 `source` 为 `int` 的场景，按顺序尝试：
  1. `CAP_DSHOW`
  2. `CAP_MSMF`
  3. 默认后端（不指定 api preference）
- 每次尝试都记录：
  - 后端标识
  - 是否 `isOpened()`
- 成功即停止，并保存 `last_backend_name` 供上层打印。
- 全部失败时抛出包含完整尝试链路的错误信息。

## 5. 验收标准
1. 对“DSHOW 不可用、MSMF 可用”的模拟场景，`CameraManager.open()` 可成功打开。
2. 对“所有后端都失败”的场景，错误消息包含尝试后端列表。
3. 现有测试继续通过，新增测试通过。
4. `main.py --camera-sources "0,1"` 运行时，日志可读性提升（能看出具体跳过原因）。

## 6. 风险与应对
- 风险：不同 OpenCV 构建对 `CAP_MSMF` 支持差异。
- 应对：保留“默认后端”第三回退，避免绑定单后端。
