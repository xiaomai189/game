# PRD - 2026-04-04 18:15 - 实机双摄回归脚本与断连提示降噪（v43）

## 1. 背景
- 当前双人模式功能可用，但“实机双摄是否持续稳定输出”缺少一键验证脚本。
- 前端在 YOLO WebSocket 断连时重连频率偏高，现场会出现较密集的错误日志与弱可读提示。

## 2. 目标
- 提供可在 Windows 本机直接执行的双摄实机回归脚本，验证 `camera 0/1` 都在 websocket 帧中持续出现。
- 优化前端断连提示与重连节奏，降低日志噪声并提升状态可见性。

## 3. 范围
- 新增：实机双摄 websocket 监听验证脚本（Python）。
- 新增：实机回归 PowerShell 包装脚本（调用 `.venv` Python）。
- 修改：`web/game/index.js` 的 websocket 重连策略与连接文案。
- 新增：Web 回归脚本验证“离线时重连节奏/状态文案”。
- 更新：`package.json`、`scripts/preflight.mjs`、`README.md`。

## 4. 非范围
- 不改 YOLO 推理模型参数与动作识别逻辑。
- 不改 dual_race 玩法规则。
- 不引入后端服务化或部署形态变更。

## 5. 方案
1. 实机验证脚本 `scripts/verify_live_dual_camera.py`
- 连接 `ws://127.0.0.1:8765`。
- 在限定时长内统计 `payload.cameras[]` 中各 `cameraId` 的有效帧计数。
- 验收条件：`cam0/cam1` 均达到最小帧数阈值，输出 PASS；否则 FAIL 并返回非 0。

2. 包装脚本 `scripts/test-live-dual-camera.ps1`
- 默认使用 `.\.venv\Scripts\python.exe`。
- 支持可配置 `-WsUrl/-TimeoutSec/-MinFramesPerCamera`。
- 输出清晰的通过/失败摘要。

3. 前端断连降噪
- 重连退避上限提升、首轮重试延后，减少失败连接频率。
- 连接条改为展示“下次重试倒计时 + attempt 次数”。
- 暴露 `window.get_transport_state()` 并写入 `render_game_to_text.transport`，用于自动化回归读取。

4. 回归脚本
- 新增 `scripts/test-web-ws-reconnect-noise.mjs`：
  - 无后端情况下启用 camera 模式并启动游戏。
  - 采样 transport 状态，断言重连次数在阈值内且 banner 文案包含 retry 信息。

## 6. 验收标准
- `npm run test:web-ws-reconnect-noise` 通过。
- `npm run build` 通过。
- `npm run preflight` 通过。
- 在实机运行（双摄接入）下，`scripts/test-live-dual-camera.ps1` 返回通过。

## 7. 风险与回滚
- 风险：重连间隔增大可能让恢复连接感知稍慢。
- 控制：仅调整到可读性与噪声平衡的保守区间，不改连接协议。
- 回滚：若体验不佳，可回滚 `web/game/index.js` 重连策略至 v42。
