# PRD：Web 多模式模块化重构（v24）

## 背景
- 当前 `web/game.js` 体量较大，包含四种玩法、渲染、输入与全局接口，单文件维护风险高。
- 用户确认“继续扩展前先拆分”，并要求保持现有体感控制接口与玩法入口兼容。

## 目标
- 将 Web 玩法实现从单文件重构为“入口调度 + 模式模块”结构。
- 保持外部调用兼容：`?mode=`、`window.switch_workout_mode`、`window.render_game_to_text`、`window.advanceTime`、`window.inject_pose_payload`。
- 通过现有回归测试与预检命令。

## 方案
1. 新增 `web/game/index.js` 作为唯一入口，负责：
   - 模式创建/切换与生命周期（start/pause/resume/restart）
   - WebSocket 姿态流接入
   - 全局函数导出与键盘快捷键映射
   - HUD 刷新与按钮状态同步
2. 新增独立模式模块：
   - `web/game/modes/classic.js`
   - `web/game/modes/sprint_lane.js`
   - `web/game/modes/squat_gate.js`
   - `web/game/modes/reaction_drill.js`
3. 将 `web/game.js` 降为轻入口，仅导入 `web/game/index.js`。
4. 修复测试稳定性问题：`tests/test_game_engine.py` 中随机重生导致的偶发失败。

## 验收标准
- `npm run preflight` 全通过。
- 两个 Web 回归脚本全通过：
  - `npm run test:web-gesture`
  - `npm run test:web-workout`
- 运行页面可看到模式切换后的状态显示，且基础可玩。

## 风险
- 模块化后如果各 mode 输出字段不一致，可能破坏已有脚本。通过统一 `renderToText` 字段约定与回归脚本兜底。
