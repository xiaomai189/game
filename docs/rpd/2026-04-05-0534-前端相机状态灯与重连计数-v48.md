# PRD - 2026-04-05 05:34 - 前端相机状态灯与重连计数（v48）

## 背景
- 后端已输出每路相机 `cameraStatus / cameraStatusReason / reconnectAttempts`，但前端 HUD 仍主要依赖文本诊断，状态不够直观。
- 双摄联调时需要快速识别哪一路异常（BLACK / RECONNECTING）以及重连是否在发生。

## 目标
- 在前端 HUD 增加每路相机状态卡片（至少 cam0/cam1）。
- 用颜色灯与简短文案展示状态：`OK / WARMUP / BLACK / RECONNECTING / OFFLINE / UNKNOWN`。
- 显示每路重连计数，便于排障和稳定性评估。

## 范围
- In Scope
  - `web/index.html`：新增相机状态卡片容器。
  - `web/styles.css`：新增状态卡片与状态灯样式。
  - `web/game/index.js`：解析 `payload.cameras[]` 新字段并刷新 UI；`render_game_to_text` 增加相机状态摘要。
  - 前端回归脚本（Playwright）验证核心路径可用。
- Out of Scope
  - 不改 YOLO 推理逻辑。
  - 不改后端双摄打开策略。
  - 不新增玩法模式。

## 方案
- 在 HUD controls 区下方添加 `camera-health-grid`，默认展示 cam0/cam1 两张卡。
- `onPose` 更新 `state.cameraRuntimeById`，从 `payload.cameras[]` 提取：
  - `connected`
  - `cameraStatus`
  - `cameraStatusReason`
  - `blackFrameStreak`
  - `reconnectAttempts`
- `updateHud` 调用 `updateCameraHealthCards`，统一映射状态颜色与文本。
- `render_game_to_text` 注入 `cameraStatus` 摘要，便于自动化回归读取。

## 验收标准
- [ ] 页面可见 cam0/cam1 状态卡，状态变化时颜色和文案同步更新。
- [ ] 可见每路重连计数字段，且随 payload 变化更新。
- [ ] `npm run build` 通过。
- [ ] 至少 1 条 Playwright 前端回归通过（含双人模式链路）。

## 风险与缓解
- 风险：状态字段缺失时 UI 抖动或报错。
- 缓解：所有字段做容错默认值，未知状态统一回退 `UNKNOWN`。
