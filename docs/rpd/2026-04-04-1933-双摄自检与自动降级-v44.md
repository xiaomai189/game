# PRD - 2026-04-04 19:33 - 双摄自检与自动降级（v44）

## 1. 背景
- 当前双摄链路在部分机器上会出现低帧率、高延迟与间歇断连，导致前端看起来“未连接/很卡”。
- 现有系统有基础健康分与自适应推理参数，但缺少启动期双摄可用性判定与运行期自动降级闭环。

## 2. 目标
- 增加启动期双摄健康自检，给出明确结论（可双人/需降级）。
- 增加运行期健康守护，在双摄不稳定时自动降级为单路可玩，在稳定后可恢复双路。
- 增强诊断信息，前端可见双摄准备状态、降级原因与自检状态。

## 3. 范围
- In Scope
  - `main.py`：新增 CLI 参数、自检流程、双摄守护状态机与 WS 诊断字段。
  - `core/utils.py`：新增健康评估与双摄守护器。
  - `config.py`：新增双摄阈值与守护参数。
  - `web/game/index.js`：自动模式切换基于后端 `dualReady`，并展示运行状态。
  - `tests/`：新增健康评估与守护器单测。
- Out of Scope
  - 不改 YOLO 模型结构与动作识别规则。
  - 不改 dual race 核心玩法与关卡机制。

## 4. 方案
- 启动自检窗口（默认 8 秒）内统计每路 pipeline 指标，生成自检结论：
  - `ok`: 双摄达标。
  - `degraded`: 至少一路不达标，自动降级到单路。
- 运行期守护：
  - 双摄 ready 状态下，连续 bad 持续超过阈值触发降级。
  - 降级后连续 good 持续超过恢复窗口后恢复双摄 ready。
- WS 输出增强：
  - 根 payload 增加 `runtime.dualRequested/dualReady/selfCheck/reason/degradedCameraIds`。
  - 各 camera pipeline 增加 `healthLevel/healthReason`。
- 前端自动模式：
  - 仅当 `runtime.dualReady=true` 才自动进入 dual race。
  - 诊断区显示 dual 状态与自检状态。

## 5. 验收标准
- [ ] `pytest -q` 通过（含新增守护逻辑单测）。
- [ ] `npm run build` 通过。
- [ ] 双摄达标时自动进入双人模式；双摄不达标时自动降级且保持可玩。
- [ ] 诊断栏可看到双摄状态与自检结论，不再只靠“是否有 cameraId”判定双人。

## 6. 风险与缓解
- 风险：阈值过严导致误降级，过宽导致体验卡顿。
- 缓解：阈值集中配置化，并通过 `--dual-min-fps/--self-check-sec/--auto-degrade` 快速调参。
