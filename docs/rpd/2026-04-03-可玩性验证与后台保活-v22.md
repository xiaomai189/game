# PRD：可玩性验证与后台保活（v22）

## 背景
- 用户反馈“看不到新的游戏”，并要求再次验证是否可以正常游玩。
- 当前 one-click 常用参数包含 `--no-display`，该模式下后端在 `GAME_OVER` 后会直接退出，导致前端 websocket 断开，体感输入中断。

## 目标
- 验证网页端四种模式可识别并可进入（`classic/sprint_lane/squat_gate/reaction_drill`）。
- 修复 `--no-display` 场景下后端自动退出问题，保证 one-click 持续可玩。
- 消除联调中发现的前端渲染崩溃（Canvas negative radius）。

## 范围
- 包含：
  - `main.py` 无显示模式保活逻辑。
  - `web/game.js` 渲染边界保护。
  - 回归测试与实机联调证据补充。
- 不包含：
  - 玩法机制改版。
  - 新模式功能扩展。

## 方案
1. **后端保活**
   - 修改 `main.py`：`args.no_display` 且 `snapshot.status == GAME_OVER` 时不退出循环，改为 `game_engine.start(...)` 自动重开局。
2. **前端稳定性**
   - 修改 `web/game.js`：对切道特效半径计算做 `clamp + min radius`，避免时间回退时 `ctx.arc` 半径为负导致报错。
3. **验证**
   - 执行 `npm run preflight`（含 `pytest/build/web回归`）。
   - one-click 启动后检查后端进程存活、前端 stream 连通、模式切换可见。

## 验收标准
- `npm run preflight` 全部通过。
- `run-oneclick.ps1 -Demo -NoDisplay` 启动后，后端不会在一局结束后自动退出。
- 前端页面无 `CanvasRenderingContext2D.arc radius negative` 报错。
- 页面可见新模式标识（示例：`Status: READY | Squat Gate`）。

## 风险与取舍
- 自动重开局会让无显示模式持续运行，适合服务桥接场景；若未来需要“单局结束自动退出”的离线批处理，可用 `--max-frames` 控制退出。
