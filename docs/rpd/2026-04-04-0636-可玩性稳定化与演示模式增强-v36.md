# PRD: 可玩性稳定化与演示模式增强 (v36)

## 1. 背景
- 当前 classic 视觉和 HUD 已完成 v35 专业化重构，但在未连接 YOLO 服务时仍有连接错误噪音，演示体验不稳定。
- 需要提升“无相机服务也能顺畅演示”的能力，并保持玩法规则不变。

## 2. 目标
- 引入输入模式体系：`auto/camera/keyboard/demo`，支持自动降级。
- 无 YOLO 服务时默认可玩（keyboard fallback），并降低连接重试噪音。
- 回合状态与操作提示保持清晰，支持快速演示。
- 增强可观测性：输出 `inputMode` 与 `uiVariant` 到文本状态。

## 3. 范围
- 前端运行层：`web/game/index.js`（输入模式、连接状态、降级与 demo 自动输入）。
- 前端界面层：`web/index.html`、`web/styles.css`（输入模式选择器与提示）。
- 游戏状态输出层：`web/game/modes/classic.js`（新增 `visual.inputMode`）。
- 自动化：新增两条 Web 回归，纳入 preflight。

## 4. 方案
- 新增 `set_input_mode/get_input_mode` 浏览器 API。
- 当 `inputMode=auto` 且 YOLO 未连接时，自动切到 keyboard 生效模式；`camera` 模式则保持重连等待。
- WebSocket 重连采用退避策略并在 UI 中展示当前输入来源状态。
- `demo` 模式提供低频自动动作注入，用于无设备演示。

## 5. 验收标准
1. 未启动 YOLO 服务时，`auto` 模式可玩且界面提示为 fallback。
2. `camera` 模式在断连时显示重连状态，不导致玩法崩溃。
3. 新增回归脚本通过：输入模式降级、回合流转按钮矩阵。
4. `npm run preflight` 全通过，并补充 v36 证据截图与记录。

## 6. 风险与应对
- 风险: 新输入模式可能影响现有测试稳定性。
- 应对: 保持现有 API 不变，新增测试覆盖输入模式逻辑与回合流程，避免行为回退。
