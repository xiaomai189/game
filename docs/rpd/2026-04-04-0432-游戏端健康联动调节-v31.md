# PRD：游戏端健康联动调节（v31）

## 1. 背景
- YOLO 端已输出 `healthScore`、`inferenceStrideFrames`、`inferenceScale`。
- 当前 `classic` 玩法尚未使用这些诊断值，识别质量波动时游戏节奏不会自适应。

## 2. 目标
- 将 YOLO 端健康分接入 `classic` 模式。
- 当健康分降低时自动降低游戏节奏（速度与刷怪频率），提升可玩性与容错。
- 保持旧玩法兼容：无 pipeline 输入时默认正常节奏。

## 3. 范围
- `web/game/index.js`：维护并传递 pipeline 指标。
- `web/game/modes/classic.js`：加入健康联动节奏调节。
- 新增 Web 回归脚本验证联动效果。

## 4. 方案
- 在 `sharedState` 中加入 `pipeline`。
- `classic` 根据 `healthScore` 计算目标节奏因子（低健康 -> 降速/拉长刷新间隔），并平滑过渡。
- 在 `render_game_to_text` 输出 `runtime` 字段，便于自动化验证。

## 5. 验收标准
1. `healthScore` 低时 `paceFactor` 低于高健康场景。
2. `npm run build`、`npm run test:web-gesture`、新增联动测试通过。
3. `npm run preflight` 全通过。

## 6. 风险与应对
- 风险：调节过强导致体验过慢。
- 应对：限制最小节奏因子并使用平滑过渡，避免突变。
