# PRD：最小可演示 Demo 闭环

## 背景
- 当前项目已具备摄像头、姿态识别、动作判定、计分与 HUD 基础能力。
- 但演示链路仍缺少完整“开局-进行中-结束”状态管理，以及无人值守可复现的演示模式。

## 目标
- 完成最小可演示 Demo：可启动、可进行、可结束、可看到得分与倒计时。
- 支持无摄像头/无模型条件下的演示运行，并生成界面证据。

## 范围
- In Scope：
  - `game_engine` 增加状态机、倒计时、命中冷却。
  - `renderer` 增加状态与倒计时显示，优化演示提示。
  - `main` 增加 `--demo` 演示模式和证据图导出能力。
  - 新增/调整测试覆盖关键状态流转与冷却行为。
  - 在 `docs/evidence/` 输出至少一张演示界面证据图。
- Out of Scope：
  - 不引入多人识别。
  - 不引入 Unity 或打包流程。
  - 不实现复杂开始菜单和动效系统。

## 方案
- 游戏状态采用：`READY -> RUNNING -> GAME_OVER`。
- `RUNNING` 状态启用倒计时，归零后进入 `GAME_OVER`。
- 命中时应用冷却窗口，防止连续帧重复加分。
- `--demo` 模式下使用合成画面与模拟动作，自动完成命中演示，支持 `--max-frames --no-display` 运行并保存最终画面。

## 验收标准
- [ ] `python main.py --demo --max-frames 300 --no-display` 可正常退出（0）。
- [ ] 画面显示状态、倒计时、分数、动作状态。
- [ ] 至少存在 1 张 `docs/evidence/` 下的演示证据图。
- [ ] 单元测试通过。

## 风险与缓解
- 风险：现场无摄像头导致无法直接展示真实识别链路。
- 缓解：提供 `--demo` 模式保证可演示，同时保留摄像头模式用于现场验证。
