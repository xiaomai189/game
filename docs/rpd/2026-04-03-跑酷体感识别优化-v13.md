# PRD：跑酷体感识别优化 v13（速度优先）

## 背景
- 当前 Web 跑酷换道在快速动作下偶发抖动和反复跳道。
- 本轮目标是保持“抬左/抬右/不抬”手势不变，仅优化换道状态机体验。

## 目标
- 在速度优先前提下，降低左右误跳道。
- 将回中确认窗口调整为 `30ms`，同时保证左右手抬起仍是即时切道。

## 范围
- In Scope：
  - 修改 `web/game.js` 换道状态机（30ms 回中确认 + 70ms 侧向锁定）。
  - 增加姿态流 `stale > 300ms` 时的输入冻结逻辑。
  - 增强 `render_game_to_text` 调试输出，方便自动验证。
  - 更新 `web/index.html` 与 `README.md` 的交互说明。
  - 执行 `npm run build`、`pytest -q`，并补充 UI 证据。
- Out of Scope：
  - 不修改 `core/action_engine.py` 的姿态阈值和模型逻辑。
  - 不调整跑酷障碍节奏与美术表现。

## 方案
- 状态机策略：
  - 侧向（左/右）输入：即时切道。
  - 切到侧道后：进入 `70ms` 侧向锁定窗口，锁定期间忽略反向侧向输入。
  - 中道输入：`30ms` 连续确认后回中；若中途出现侧向输入则取消回中计时。
  - 双手同抬：保持当前车道。
  - 流中断：`stale > 300ms` 时冻结换道输入，不自动回中。
- 可观测性：
  - 输出 `intentLane`、`switchLockMsLeft`、`centerCommitMsLeft` 供 Playwright 采集。

## 验收标准
- [ ] 左右手抬起后可即时切道。
- [ ] 反向抖动在 `70ms` 锁定期内不触发反向跳道。
- [ ] 双手放下约 `30ms` 后回中。
- [ ] 流中断时保持当前道，不出现自动漂移。
- [ ] `npm run build` 通过。
- [ ] `pytest -q` 通过。
- [ ] UI 证据与状态证据落盘到 `docs/evidence/`。

## 风险与缓解
- 风险：速度优先下仍可能出现少量误触发。
- 缓解：本轮保留调试输出，下一轮可按证据追加“动态阈值”或“短帧确认”。
