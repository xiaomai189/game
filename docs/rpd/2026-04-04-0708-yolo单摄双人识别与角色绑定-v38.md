# PRD: YOLO 单摄双人识别与角色绑定（v38）

## 1. 背景
- 当前 YOLO 侧默认只输出主目标单人姿态，Web payload 也主要面向单人动作。
- 下一阶段目标是先完成“单摄双人可观测”，并保持现有游戏链路不回归。

## 2. 目标
- 在单摄像头输入下，稳定输出最多 2 人姿态与动作信息。
- 引入 `P1/P2` 角色绑定：先按左右站位分配，再按 `track_id` 锁定。
- 对外保持兼容：现有单人字段继续可用，同时新增 `persons/roles` 扩展字段。

## 3. 范围
- `core/pose_engine.py`：扩展多人提取、主目标与 top-2 选择。
- `core/action_engine.py`：新增双人动作推理与角色绑定器。
- `core/web_payload.py`：新增 `persons/roles` 输出，保持旧字段不变。
- `main.py`、`config.py`：新增 v38 参数与运行接线。
- `tests/`：补充 pose/action/web_payload 的双人回归测试。

## 4. 方案
- `PoseEngine` 在一次推理中输出：
  - `primary keypoints`（兼容旧链路）
  - `persons[]`（最多 2 人，含 `track_id/bbox/keypoints/score`）
  - `primary_track_id`
- `ActionEngine` 新增 `infer_multi`：
  - 每人独立动作状态（复用单人判定逻辑）
  - 角色绑定策略：
    - 初始按 x 坐标分 `P1(left)/P2(right)`
    - 之后按 `track_id` 粘住
    - 短时丢失保留 `grace_ms=500`
- `build_web_payload` 新增：
  - `persons[]`
  - `roles: {p1, p2}`
  - 保留旧字段 `actions/hands/body`
- `main.py` 增加可选参数：
  - `--max-persons`
  - `--role-bind-grace-ms`
  - `--disable-dual-role`

## 5. 验收标准
1. 单摄场景下 payload 能输出最多 2 人，且包含 `track_id` 与动作字段。
2. `roles.p1/p2` 能稳定跟随同一 `track_id`（短时丢失不立即换位）。
3. 原有单人链路字段继续可用，不影响现有 web/game 运行。
4. `pytest -q` 与 `npm run build` 通过。

## 6. 风险与应对
- 风险：多人识别导致主目标抖动，影响旧玩法。
- 应对：保留原主目标选取策略，新增多人输出为增量字段；若多人失败，主目标仍可独立工作。
