# PRD：跑酷节奏调优 v7（降低速度与生成密度）

## 背景
- 用户反馈障碍切换频率过高，实操中“基本来不及”。
- 当前参数导致中后期障碍到达间隔过短，演示体验偏硬核。

## 目标
- 将 Web 跑酷调为更适合演示的节奏：
  - 降低障碍下落基础速度。
  - 拉大障碍生成间隔，并限制最小间隔不低于约 900ms。
- 保持玩法不变（3 道、手势换道、下蹲护盾）。

## 范围
- In Scope：
  - 修改 `web/game.js` 节奏相关常量与计算公式。
  - 运行 `npm run build`。
  - 补充变更记录和证据。
- Out of Scope：
  - 不修改后端姿态识别。
  - 不修改 UI 布局或控制按钮逻辑。

## 方案
- 参数调整：
  - `worldSpeedBase: 300 -> 240`
  - 速度增长由 `min(180, score * 1.6)` 调整为 `min(120, score * 1.2)`
  - 生成间隔由 `860 - ratio*280` 调整为 `1150 - ratio*250`（最小约 `900ms`）
- 预期效果：
  - 障碍到达时间增加，操作窗口变大。
  - 单位时间换道需求下降，提升可玩性与演示稳定性。

## 验收标准
- [ ] `npm run build` 通过。
- [ ] 游戏主观体验明显变得“可反应”，不再高频压迫。
- [ ] 中后期障碍间隔保持在约 `0.9s` 及以上。

## 风险与缓解
- 风险：难度下降过多导致挑战性不足。
- 缓解：后续可增加“普通/困难”两档参数开关。
