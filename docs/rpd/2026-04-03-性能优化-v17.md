# PRD：体感链路性能优化 v17（实机体验优先）

## 背景
- 现有功能闭环已建立（动作稳定、Web 回归、CI 门禁），但主循环缺少性能调优机制与统一性能指标。
- 在普通 Windows PC 场景下，推理与渲染负载波动会影响体感响应连贯性。

## 目标
- 在不改动作语义和玩法规则前提下，降低端到端延迟并提升运行平稳性。
- 增加可量化性能指标输出，支持本地性能采样与回归对比。

## 范围
- In Scope：
  - 新增推理步长控制（inference stride）。
  - 新增自适应推理分辨率（默认 1.0 与 0.75 两档）。
  - 新增性能指标统计与 Web payload 扩展字段（可选，不破坏兼容）。
  - 新增性能报告导出参数（JSON）。
  - 更新 README、补变更记录与证据。
- Out of Scope：
  - 不修改动作判定语义规则。
  - 不修改 Web 跑酷交互规则（30ms/70ms/stale）。
  - 不更换模型或引入新推理框架。

## 方案
- 主循环优化：
  - 每 N 帧执行一次推理，其余帧复用最近一次关键点结果。
  - 当性能压力升高时，推理输入降到 0.75 尺寸；恢复后自动回到 1.0。
- 指标统计：
  - 统计 capture/infer/render FPS、p95 延迟、丢帧率。
  - 通过 Web payload 的 `pipeline` 字段对外输出。
- 配置项：
  - `inference_stride_frames`
  - `drop_stale_frames`
  - `adaptive_resolution_enabled`
  - `latency_budget_ms`
  - `inference_downscale_ratio`
- 性能报告：
  - 新增 `--perf-report` 参数，运行后输出 JSON 报告到指定路径。

## 验收标准
- [ ] `pytest -q` 通过。
- [ ] `npm run build` 通过。
- [ ] `npm run test:web-gesture` 通过。
- [ ] 默认配置下程序可正常运行，Web payload 保持向后兼容。
- [ ] `--perf-report` 可生成有效 JSON 报告。

## 风险与缓解
- 风险：推理步长过高会降低动作更新频率。
- 缓解：默认步长为 `1`，仅在明确调参后提高。
- 风险：下采样推理可能降低关键点精度。
- 缓解：仅在延迟超预算时触发，恢复后自动回升。
