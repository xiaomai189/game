# Change Log - 2026-04-04 07:42 - 双摄像头打开回退与诊断增强（v40）
## 改动内容
- `core/camera.py`
  - 为索引相机增加后端回退：`DSHOW -> MSMF -> DEFAULT`。
  - 新增 `last_backend_name`、`open_attempts` 诊断字段。
  - 打开失败异常改为携带完整后端尝试链路。
- `main.py`
  - 相机打开成功后打印后端信息：
    - `Camera[i] ready: source=... backend=...`
- `tests/test_camera.py`
  - 新增 3 条单元测试：
    - DSHOW 失败后回退 MSMF 成功
    - 全部后端失败时报错信息包含尝试链路
    - 字符串源仅使用 DEFAULT

## 改动原因
- 现场日志显示第二路相机在 DSHOW 上失败，且原日志无法判断是否已尝试其它后端。
- 需要在不改动玩法和推理逻辑的前提下，提高多摄像头打开兼容性和排障效率。

## 验证结果
- `.\.venv\Scripts\python.exe -m pytest -q`：通过（33 passed）。
- `.\.venv\Scripts\python.exe main.py --camera-sources "0,1" --max-frames 10 --no-display --disable-websocket`：已执行。
  - 在当前环境两路均不可用，但日志已完整输出失败链路：
    - `Camera[0] skipped: ... Tried backends: DSHOW -> MSMF -> DEFAULT`
    - `Camera[1] skipped: ... Tried backends: DSHOW -> MSMF -> DEFAULT`
  - 说明诊断增强生效，可直接用于现场定位设备索引/权限问题。

## 结论
- 代码层面已支持双摄并行打开与回退。
- 当前机器实际只成功打开一路摄像头，第二路需检查硬件、系统权限或设备索引。
